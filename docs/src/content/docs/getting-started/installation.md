Install omh and check it runs. It takes about two minutes; nothing on this page
touches a repository yet.

## Before you begin

You need:

- **Docker, running.** It is the only runtime verified end to end — see
  [runtime backends](/concepts/architecture/#runtime-backends).
- **git**, and a repository to work in. omh refuses to run outside one.
- **macOS or Linux**, on arm64 or x86_64.

## Install

Pick one. Homebrew is the easiest to keep up to date.

### Homebrew

```console
$ brew install mindsers/tap/omh
```

The formula lives in [mindsers/homebrew-tap](https://github.com/mindsers/homebrew-tap)
and is generated by omh's own release pipeline, so its checksums are the ones
the release published.

### The install script

```console
$ curl -fsSL https://ohmyharness.sh/install.sh | sh
```

It picks the build for your OS and architecture, checks it against the
release's `SHA256SUMS`, and installs it to `~/.local/bin`. A failed download or a
checksum that does not match stops the install, and a failed install never
replaces a working `omh`.

<details>
<summary>What the script reads, and where that URL goes</summary>

The URL redirects to [`install.sh`](https://github.com/mindsers/ohmyharness/blob/main/install.sh)
in the omh repository — a redirect rather than a copy, so the script you pipe to
`sh` is the one you can read there. Linux builds are static musl, so one build
covers every distribution.

| Variable | What it does |
|---|---|
| `OMH_VERSION` | the tag to install, instead of the latest |
| `OMH_BIN_DIR` | where the binary goes (default `~/.local/bin`) |
| `OMH_BASE_URL` | where to fetch from — for mirrors, and for testing the script. Pair it with `OMH_VERSION`: resolving *latest* always asks github.com |

</details>

### From source

You need Rust 1.88 or later.

```console
$ git clone https://github.com/mindsers/ohmyharness && cd ohmyharness
$ cargo build --release
$ cp target/release/omh ~/.local/bin/      # or put target/release on PATH
```

1.88 is the `rust-version` in `Cargo.toml`, and CI builds the whole tree on
exactly that version — a floor something checks, not the version that happened
to be on the maintainer's machine.

## Check it works

```console
$ omh --version
```

It prints the version you installed. If your shell says `command not found`,
the directory omh went into is not on your `PATH`: for the script, that is
`~/.local/bin`.

## Keep it up to date

| You installed with | Update with |
|---|---|
| Homebrew | `brew upgrade omh` |
| the install script | run the same `curl … \| sh` line again — nothing in `install.sh` updates itself |
| source | `git pull`, then build and copy again |

After an update, run [`omh upgrade`](/reference/commands/#omh-upgrade) in a repo
you already set up: it refreshes your catalogue and rebuilds the images whose
recipe moved.
